## 二、原理

### 2.1 两个坐标系

```
转子侧（编码器所在）          输出端（关节）
      p                        q = p / N
```

- `data.q` 是**转子侧**角度（rad）；
- 减速比 `N ≈ 6.33`（精确定义 19:3），所以输出端角度 = 转子侧 ÷ N；
- 程序内部所有角度**统一用输出端**，只有下发给 SDK 时才换算回转子侧。

### 2.2 两条核心公式

```
反馈：  q     = data.q / N + offset
指令：  cmd.q = (q_des - offset) * N
刚度阻尼：cmd.kp = KP_out / N² ,  cmd.kd = KD_out / N²
```

`offset` 就是**零点偏移**：改 `offset` ＝ 移动软件零点。

### 2.3 单圈绝对值编码器与 6.33 个候选零点

编码器装在**转子**上、是**单圈绝对值**：

- **绝对值**：上电直接能读到当前角度，不用找零；
- **单圈**：只保证这一圈内绝对，**掉电后圈数丢失**，上电只报 0~360°（转子侧）。

因为减速比 N ≈ 6.33，所以：

- 输出端一整圈 = 转子转 6.33 圈 = 编码器零点被经过 **6.33 次**；
- 输出端有 **N ≈ 6.33 个候选零点**，相邻间距

```
LOBE = 360° / N ≈ 56.85°   （输出端）
```

- 上电瞬间，电机只报“最近一次经过的那个零点往正方向走了多少”，
  所以读数**永远落在 0 ~ 56.85°**，到底属于哪个候选零点**并不确定** —— 这就是**零点跳变**的物理根源。

> 结论：单圈编码器无法自行区分“差一个零点间距”的情况，必须借助外部信息
> （上次姿态记忆，或人工确认的标记零点）。这不是程序偷懒，是物理限制。

## 四、运行方法

### 4.1 环境要求

- Ubuntu / Linux（x86_64 或 ARM64）
- Python 3.10（或 3.8；`.so` 版本必须与 Python 版本匹配）
- 宇树 USB 转串口（默认 `/dev/ttyUSB0`）
- 需要 `sudo`（直接访问串口设备）

### 4.2 接线与上电

1. 用 USB 转串口连接电机，确认设备号：

   ```bash
   ls /dev/ttyUSB*
   ```

2. 如果设备号不是 `/dev/ttyUSB0`，修改 `motor_zero.py` 第 47 行：

   ```python
   SERIAL_NAME = "/dev/ttyUSB0"
   ```

3. **做好保护**：电机固定牢靠，输出端不要带负载/夹手；首次测试建议空载。

### 4.3 启动

方式一（推荐，一键脚本）：

```bash
cd "第3次作业--motor电机的驱动"
./run.sh
```

方式二（手动）：

```bash
cd "第3次作业--motor电机的驱动/python"
sudo env LD_LIBRARY_PATH=../lib python3 motor_zero.py
```

> 必须带 `LD_LIBRARY_PATH=../lib`：`unitree_actuator_sdk` 的 `.so` 需要找到
> `libUnitreeMotorSDK_Linux64.so`。`run.sh` 已自动处理。

| `shift [deg]` | 零点沿**正方向**平移 deg°（默认 30°） | 任务 3 |
| `lobe [+n/-n]` | 零点整体平移 n 个候选零点间距（≈56.85°） | 修“认错零点” |
| `home` | 重新缓慢回到 0° | |
| `damp` | 进入阻尼模式（可自由拖动） | |
| `status` | 打印当前状态 | |
| `save` | 手动保存配置 | |
| `help` | 显示帮助 | |
| `quit` / `Ctrl-C` | 阻尼退出 | |

### 5.2 首次使用：标定零点

1. 运行程序，等待回零结束；
2. 手动把电机输出端停在**你标记的零点**；
3. 输入：

   ```
   set 0
   ```

   程序会把“当前位置”定义为 0°，并把零点偏移写入配置文件。

### 5.3 任务 2 操作

```
等待回零 → 输入 45 → 电机缓慢转到 45°
```

### 5.4 任务 3 操作（零点正向偏移 30°）

```
回零 → 输入 45 → shift 30 → 再输入 45
```

- `shift 30` 后电机**原地不动**，但显示角度从 45° 变成 15°；
- 再输入 `45`，电机转到“新的 45°”，物理上比原来多转了 30°；
- 对照记号笔标记检查是否符合预期。

### 5.5 任务 4 操作（跳变测试）

1. 断电，手动把输出端转到标记零点附近（零点**之前和之后**都试）；
2. 重新上电，观察程序输出：
   - 若显示“检测到零点可能跳变”，按提示选择；
   - 一般按**回车**（采用记忆推断）；
3. 输入任务 3 的角度，观察是否还发生跳变。

## 六、变量与数学关系

### 6.1 变量总表

| 变量 | 定义 | 含义 |
|---|---|---|
| `data.q` | SDK 反馈 | **转子侧**角度（rad） |
| `N` | `queryGearRatio()` | 减速比 ≈ 6.33 |
| `LOBE` | `2π / N` | 相邻候选零点间距（输出端）≈ 56.85° |
| `raw_meas` | `data.q / N` | **未归一化**的输出端上电读数（一般 ∈ [0, LOBE)） |
| `raw_norm` | `-floor(raw_meas/LOBE) * LOBE` | 归一化常数，把读数平移到 [0, LOBE)；正常为 0 |
| `raw0` | `raw_meas + raw_norm` | **归一化后**的上电读数 ∈ [0, LOBE) |
| `raw()` | `data.q/N + raw_norm` | 当前输出端原始读数（运行中连续，可正可负） |
| `offset` | 配置值 | 零点偏移（输出端 rad）；`q = raw + offset` |
| `q` / `q_now()` | `raw() + offset` | 软件看到的输出端角度 |
| `last_q` | 配置值 | 上次退出时的软件角度（下次上电做连续性推断） |
| `q_ref` | `raw0 + offset` | 若本次与上次同一零点，本次应读到的角度 |
| `diff` | `last_q - q_ref` | 与记忆的差 |
| `n` | `round(diff / LOBE)` | 需要补偿的零点间距个数 |
| `resid` | `diff - n * LOBE` | 补完后剩余的误差（\|resid\| ≤ LOBE/2） |
| `q_cmd` | 插值后的下发角度 | 每周期向 `target` 逼近 |
| `target` | 目标角度 | 键盘输入或 0 |

### 6.2 公式链

```
转子读数 data.q (rad)
   │ ÷ N
   ▼
raw_meas = data.q / N                     未归一化输出端读数
   │ + raw_norm = -floor(raw_meas/LOBE)*LOBE
   ▼
raw = data.q / N + raw_norm               输出端原始读数（连续）
   │ + offset
   ▼
q = raw + offset                          软件看到的关节角
```

跳变补偿：

```
raw_meas = k·LOBE + f ,  k = floor(raw_meas/LOBE),  f ∈ [0, LOBE)
raw0     = f
q_ref    = raw0 + base_offset
diff     = last_q - q_ref
n        = round(diff / LOBE)
resid    = diff - n·LOBE
offset_new = base_offset + n·LOBE
q_now    = raw + offset_new = last_q - resid
```

### 6.3 `math.floor` 在这里的作用

`math.floor(x)` = **向下取整**（≤ x 的最大整数）：

```
floor(2.7)    = 2
floor(0.3)    = 0
floor(-0.468) = -1      ← 注意：不是 0（int(-0.468) 才是 0）
```

所以 `-floor(raw_meas/LOBE)*LOBE` 就是“把 `raw_meas` 平移到 `[0, LOBE)` 需要加的常数”。
例：`raw_meas = -0.4646`、`LOBE ≈ 0.9927` → `floor(-0.468) = -1` → `raw_norm = +0.9927` → `raw0 = 0.5281`（≈30.26°）。

## 七、零点跳变处理（核心）

### 7.1 上电流程

```python
self.damp(100)                                      # 先阻尼，拿稳定反馈
raw_meas = self.data.q / N                          # 未归一化读数
self.raw_norm = -math.floor(raw_meas / LOBE) * LOBE # 归一化常数
raw0 = raw_meas + self.raw_norm                     # ∈ [0, LOBE)
base_offset = self.offset
q_ref = raw0 + base_offset

diff  = self.last_q - q_ref
n     = int(round(diff / LOBE))
resid = diff - n * LOBE

if n == 0:
    self.offset = base_offset                       # 没跳变
else:
    self.offset = self._confirm_jump(base_offset, raw0)  # 弹确认
```

### 7.2 确认界面选项

| 输入 | 含义 | 返回的 offset |
|---|---|---|
| **回车** / `y` / `ok` | 采用记忆推断，补 n 个间距 | `base_offset + n*LOBE` |
| `+` | 补偿 +1 个间距 | 刷新后重新确认 |
| `-` | 补偿 −1 个间距 | 刷新后重新确认 |
| `z` | 把当前位置直接设为 0° | `-raw` |
| `k` | 不补偿，沿用原 offset | `base_offset` |

> 提示只打印一次，不会刷屏；只有输入 `+/-` 时才更新一次。

### 7.3 五个例子

假设已标定：标记零点处 `raw = 0`、`offset = 0`，所以 `q = raw`；`LOBE ≈ 56.87°`。

| 例 | 上次 `last_q` | 动作 | 真实角 θ | `raw0` | `n` | `resid` | `q_now` | 弹窗？ | 正确操作 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 40° | 不动 | 40° | 40.00° | 0 | 0° | 40.00° | 否 | — |
| 2 | 50° | +20° | 70° | 13.13° | +1 | −20° | 70.00° | **是** | 回车 |
| 2b | 50° | −20° | 30° | 30.00° | 0 | +20° | 30.00° | 否 | — |
| 3 | 0° | +20° | 20° | 20.00° | 0 | −20° | 20.00° | 否 | — |
| 3b | 0° | −20° | −20° | 36.87° | −1 | +20° | −20.00° | **是** | 回车 |
| 4 | 0° | +40° | 40° | 40.00° | −1 | +16.87° | −16.87° ❌ | **是** | `k` 或 `+` |
| 5 | 0° | 摆到 −2° | −2° | 54.87° | −1 | +2° | −2.00° | **是** | 回车 |

#### 例 1：上次 40°，断电重启没动

```
raw0 = 40° → diff = 0 → n = 0 → q_now = 40° ✅（不弹窗）
```

之后 `GO_ZERO`，从 40° 缓慢回 0°，约 4.7 s。

#### 例 2：上次 50°，断电后手动 +20°

```
真实角 = 70°
raw0   = 70 - 56.87 = 13.13°
diff   = 50 - 13.13 = 36.87°
n      = round(36.87/56.87) = +1
resid  = 36.87 - 56.87 = -20°
offset = 0 + 56.87 = 56.87°
q_now  = 13.13 + 56.87 = 70° ✅
```

弹窗 → 按**回车** → 正确显示 70°；之后回零约 8.1 s。

#### 例 3：上次 0°，断电后手动 +20°

```
真实角 = 20°
raw0   = 20°
diff   = 0 - 20 = -20°
n      = round(-20/56.87) = 0
resid  = -20°
q_now  = 20° ✅（不弹窗）
```

之后回零约 2.3 s。

#### 例 4：上次 0°，断电后手动 +40°（超过半个间距）

```
raw0   = 40°
diff   = -40°
n      = round(-40/56.87) = -1
resid  = -40 + 56.87 = +16.87°
offset = -56.87°
q_now  = 40 - 56.87 = -16.87° ❌（正确应为 +40°）
```

因为 40° > 半个间距 28.4°，单圈编码器无法区分，程序按“离 last_q 最近”选错。
此时应输入 **`k`**（不补偿）或 **`+`**（把 n 从 −1 调到 0），即可得到正确的 40°。

#### 例 5：经典“认错零点”（上次 0°，重启时摆到 −2°）

```
raw0   = -2 mod 56.87 = 54.87°
diff   = -54.87°
n      = round(-54.87/56.87) = -1
resid  = +2°
offset = -56.87°
q_now  = 54.87 - 56.87 = -2° ✅
```

弹窗 → 按**回车** → 正确显示 −2°。这就是课程里“10° 变 350°、补一个间距”的情况。

### 7.4 三条规律

1. **弹不弹窗只看 `n`**：`n = round((last_q - raw0 - offset) / LOBE)`。
   - `n = 0` → 静默继续；
   - `n ≠ 0` → 弹确认。
2. **回车 = 取“离上次姿态最近的候选零点”**，在**净位移 < 28.4°（半个间距）**时一定正确。
3. **`z` = 把眼前位置直接当作 0°**（会丢掉原标定）；想保留原标定只是恢复角度，应**回车**（或 `k`）。

## 八、配置文件 `motor_zero_cfg.json`

程序首次运行会在 `python/` 下自动生成该文件（也可从 `motor_zero_cfg.example.json` 复制）。

```json
{
  "zero_offset_rad": 0.4690055502957433,
  "last_q_rad": 0.004357300943503617,
  "last_raw_rad": -0.4646482493522397,
  "gear_ratio": 6.329999923706055
}
```

| 字段 | 含义 | 说明 |
|---|---|---|
| `zero_offset_rad` | 零点偏移（输出端 rad） | `q = data.q/N + 此值`；改零点就是改它 |
| `last_q_rad` | 上次退出时的软件角度（rad） | 下次上电做连续性推断，**最关键** |
| `last_raw_rad` | 上次退出时的原始读数 | 仅记录/诊断，程序不读取 |
| `gear_ratio` | 记录当时减速比 | 仅记录，程序实际用 `queryGearRatio()` |

- `persist()`（`set/offset/shift/lobe/save` 后）写 `zero_offset_rad`；
- `shutdown()`（Ctrl-C/`quit`）写全部四个字段；
- 写文件采用“先写 `.tmp` 再原子替换”，防止写坏。

## 九、常见问题

### Q1：提示“无效输入”？

这是**零点跳变确认界面**，只接受：

```
回车 / + / - / z / k
```

数字角度请先按回车结束确认，回到正常模式再输入。

### Q2：为什么有时候上电会弹“检测到零点可能跳变”？

说明本次读数与 `last_q` 相差了整数个 `LOBE`。可能原因：

- 上电姿态和上次不同；
- 断电后手动搬动过输出端。

按回车采用记忆推断即可；如果明确知道搬了多少，可用 `k`/`z`/`+/-` 修正。

### Q3：半个间距（28.4°）是什么边界？

“离上次姿态最近的候选零点”只在**净位移 < LOBE/2 ≈ 28.4°** 时正确。
超过时（例如例 4 的 +40°），编码器无法区分，需要人工选 `k`/`z`。

### Q4：报错打不开串口？

- 确认 `ls /dev/ttyUSB*`；
- 确认使用了 `sudo`；
- 确认 `SERIAL_NAME` 与设备号一致；
- 确认没有被其他程序占用。

### Q5：`ImportError: libUnitreeMotorSDK_Linux64.so: cannot open shared object file`

没有设置库路径。用：

```bash
sudo env LD_LIBRARY_PATH=../lib python3 motor_zero.py
```

或直接 `./run.sh`。

### Q6：`.so` 与 Python 版本不匹配

`unitree_actuator_sdk.cpython-310-...so` 对应 Python 3.10，
`...cpython-38...so` 对应 Python 3.8。用 `python3 --version` 确认版本。
